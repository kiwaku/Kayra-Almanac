# Agent Maintenance Guide

This file documents maintenance requirements for machine-readable files in this repo. Update when adding routes, projects, or changing identity facts.

## Files Requiring Manual Updates

### 1. `llms.txt` (repo root)
**Update when:**
- New project added → add entry to "Pages" section (link-index format)
- New top-level route added → add entry to "Pages" section
- Identity facts change (role, certification, venture status, metrics) → update H1/blockquote summary
- Contact info changes → update "Contact" section
- Last-updated date → change to today (YYYY-MM-DD)

**Format:** `[Name](https://kayra-almanac.vercel.app/route): one-line description`

> **Note:** `llms.txt` is manually maintained. While the route list *could* be scripted from `src/pages/` + `src/content/projects/`, the one-line descriptions require human curation. Remember to update it on every route/project addition.

### 2. `robots.txt` (repo root)
**Update when:**
- New AI crawler user-agents emerge (add explicit `User-agent: X` + `Allow: /` block before catch-all)
- Sitemap URL changes (currently points to auto-generated `sitemap-index.xml`)

**Do NOT gate any crawlers.** Policy: all explicitly allowed.

### 3. `sitemap.xml` (repo root) — **REMOVED**
Was a manual file but **superseded** by `@astrojs/sitemap` integration.
- The auto-generated `sitemap-index.xml` + `sitemap-0.xml` in `dist/` at build time includes ALL routes (static + dynamic logbook/notebook/project pages).
- `robots.txt` points to `sitemap-index.xml` (the authoritative one).
- **No manual sitemap file exists at repo root anymore.**

## Files Auto-Updated at Build

### `sitemap-index.xml` / `sitemap-0.xml` (in `dist/`)
Generated by `@astrojs/sitemap` integration from actual route list.
- Adds new routes automatically when pages are added to `src/pages/`.
- Includes dynamic routes: `/logbook/[slug]`, `/notebooks/[slug]`, `/projects/[slug]`.
- **No manual action required.**

### JSON-LD WebSite Schema (in `src/layouts/BaseLayout.astro`)
Minimal `@type: "WebSite"` schema using `profile` data.
- `name`, `url`, `description`, `inLanguage`, `dateModified` pull from `src/data/profile.ts`.
- **Update `profile.ts`** to change schema values.
- **Person entity intentionally omitted** — lives on blog only (avoids split identity in AI summaries).

## Profile Data Source
`src/data/profile.ts` — single source of truth for:
- Name, title, email, links (portfolio, GitHub, LinkedIn, resume, CRTO, etc.)
- `siteUpdated` / `siteUpdatedDisplay` — update when deploying significant changes

## Adding a New Project
1. Add `.mdx` to `src/content/projects/` → auto-picked up by `/projects/[slug]` route
2. Add entry to `llms.txt` "Pages" section
3. Update `profile.ts` `siteUpdated` if significant
4. Deploy → auto-generated sitemap includes new route

## Adding a New Top-Level Route
1. Add `.astro` to `src/pages/` → auto-picked up
2. Add nav link in `src/components/LeftNav.astro` + `src/layouts/BaseLayout.astro` footer
3. Add entry to `llms.txt` "Pages" section
4. Update `profile.ts` `siteUpdated`
5. Deploy

## Verification Commands

# Check auto-generated sitemap

# Verify JSON-LD in output
grep -A 10 'application/ld+json' dist/index.html

# Check llms.txt is accessible
