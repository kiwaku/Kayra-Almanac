Custom LibreWolf is a reproducible, dotfiles-style privacy stack for a single Mac: a local recursive DNS resolver, a hardened LibreWolf browser, a self-hosted SearXNG instance, and a custom WebExtension that exposes the whole stack in a toolbar popup. The repo is single-user and native — no containers in the hot path, no cloud middleware, no third-party gates between the laptop and the network. The whole stack runs on loopback, and a fresh Mac with Homebrew, LibreWolf, and the repo cloned reaches the same end state with one command: `./install.sh`.

The project started in late April 2026 as a deliberate consolidation: a single repo whose `install.sh` could rebuild the privacy posture from scratch on a clean machine, with every decision recorded against the failure mode it avoids. The **WHY** lives in `README.md`. The **WHAT/WHERE** lives in `GROUND_TRUTH.md`. The ordered **DO-THIS** walkthrough lives in `MANUAL_SETUP.md`. Every load-bearing decision below is one of those three documents condensed.

### At a glance

- **Install path:** `/Applications/Browsers/LibreWolf.app` (custom — not the default). Every script, launcher, and policy reapply in this repo targets this path; the path is not parameterised.
- **DNS:** dnsmasq (`127.0.0.1:53`) → Unbound (`127.0.0.1:5335`) with DoT to Quad9 + Mullvad + Control D. Phase 2 adds an Unbound dnstap → Python collector → Unix-socket → native-messaging pipeline for per-query forwarder attribution surfaced in the browser popup.
- **Browser:** LibreWolf with the arkenfox baseline + a project-specific overlay + per-profile overlays. Two named profiles: `daily` (logged-in, FPP-on, locale-correct) and `clean` (session-only, WebGL off, sanitize-on-shutdown). Tor Browser is the third posture and is run unmodified.
- **Search:** SearXNG native via launchd `app.searxng` on `127.0.0.1:8888`. Four primary engines — DDG, Brave, Mojeek, Karmasearch — fan out via in-process `curl_cffi` (Chrome-shaped TLS) and bypass SearXNG's httpx outgoing client. Google / Bing / Yandex (and every category variant — `google_images`, `bing_news`, …) are blocked.
- **Cadence:** weekly launchd agent on Sunday 03:00 runs `brew upgrade --cask librewolf` and reapplies the in-bundle policies. A daily 09:00 RSS tripwire polls Mozilla Security Advisories and posts a macOS notification on new GUIDs so the user can upgrade early.
- **Extension:** `librewolf-extensions/privacy-stack-viewer/` — custom MV3 WebExtension. Toolbar popup shows the active tab's TLS state, the DNS forwarder that resolved its hostname, and live SearXNG engine stats when the active tab is the local search page.

### Three postures, three profiles

**Each profile has one coherent threat model. Don't smear them.**

| Profile | Posture | Use for | Don't use for |
|---|---|---|---|
| **daily** | Comfortable, logged-in, locale-correct (Tokyo). RFP off, FPP on (per-eTLD+1 randomisation). Protected by containers + arkenfox baseline + local DNS stack. | Everyday browsing, logged-in services, per-identity tabs via Multi-Account Containers. | Sketchy/research browsing — your logins de-anonymise you to anyone watching the fingerprint. |
| **clean** | Pseudonymous. RFP off, FPP on. WebGL off. Session-only state, no logins, no persistence — sanitize-on-shutdown wipes cache/cookies/history/sessions on close. | Sensitive clearnet research, one-off links, anything you don't want polluting daily's state. | Logging into anything you also use in daily. Onion content (use Tor Browser). |
| **Tor Browser** | Anonymous. Tor Project's posture, unmodified. | Onion-link retrieval, anything where IP-level anonymity matters. | Anything where you'd be tempted to "fix" the layout, locale, or fingerprint defaults — those defaults are calibrated for the Tor Browser user crowd; breaking them deanonymises you. |

**Discovery vs retrieval:** SearXNG (any profile) finds onion URLs. Tor Browser loads them. LibreWolf-with-hardening is **not** a Tor Browser substitute — Tor Browser ships patches Firefox doesn't (proper first-party isolation, timing-attack mitigations, RFP calibrated to its user base, bundled Tor daemon with circuit isolation).

**One activity, one profile, clear boundary.** If you find yourself wanting to mix, that's the signal you need a fourth profile (e.g. `work`) — add it via the documented overlay pattern, don't compromise an existing one.

## Why each piece

Each design choice has a failure mode it avoids. The alternatives were considered and rejected for the reasons given.

### Why a local DNS stack

Goal: **visibility + no upstream trust.** A caching forwarder on `127.0.0.1:53` gives per-query logs — you can see what every application on the Mac looks up. Behind it, Unbound does full recursive resolution with DoT to a diversified upstream set. The alternative — pointing the system at 1.1.1.1 or 8.8.8.8 — means a third party sees every name your Mac resolves. With DoH kill-switched in LibreWolf (`network.trr.mode = 5`), all name traffic goes through this stack. If DNS breaks, browsing breaks visibly — that failure mode is intentional.

### Why SearXNG, self-hosted

Goal: **same "trust no upstream" posture as DNS, applied to search.** A remote SearXNG instance still funnels every query through its operator; Firefox's built-in search picker still sends each query to whichever engine won that query. Running SearXNG on `127.0.0.1:8888` means queries fan out from *your* Mac to multiple engines, weighted, with Google / Bing / Yandex explicitly disabled — they are the main aggregators, their absence is the privacy win. DDG, Brave, Mojeek, Karmasearch carry the query load. The instance binds to loopback only, never `0.0.0.0`, so it's not exposed on the LAN.

### Why two profiles (`daily` and `clean`)

Goal: **real disk-level isolation, not just cookie-jar isolation.** Containers (Multi-Account + Temporary) separate cookies, cache, and site storage *within* a profile — they share IndexedDB quota, extension storage, and every other per-profile database. A second on-disk profile gives a fully separate storage graph: a rogue extension or an IndexedDB exploit in `daily` can't reach `clean`. `clean` is uBlock-only, starts every tab in a fresh Temporary Container, and never logs into anything.

### Why FPP, not RFP

Goal: **defeat cross-site fingerprint correlation without breaking the daily browsing experience.** Resist Fingerprinting (`privacy.resistFingerprinting = true`) forces `en-US` locale + UTC timezone — a Tokyo user gets wrong-language content and wrong-timestamp UI — enables letterboxing, and produces a uniform Tor-shaped signature that Cloudflare / Akamai WAFs treat as bot traffic. The RFP-strict use case is handled by running **Tor Browser separately**. FPP (per-eTLD+1 randomisation, Brave-farbling-style) defeats correlation while leaving locale and timezone alone. Within-session identity stays stable; logins persist. Both prefs are pinned explicitly so a future LibreWolf default flip can't silently swap the posture.

### Why prefs + policies over extensions

Goal: **fewer moving parts, no extension bloat.** A `user.js` pref is one line in a text file; an extension is code you trust, maintained by a person who may stop maintaining it, with its own storage and attack surface. Anything that can be done via a pref (DoH off, first-party isolation, telemetry off, speculative-connect off) *is* done via a pref. Extensions are reserved for things Mozilla can't do in-tree: uBlock Origin, container management, codec negotiation.

### Why a reapply script

Goal: **survive Homebrew cask upgrades.** `brew upgrade --cask librewolf` replaces the `.app` bundle wholesale — anything written into `Contents/Resources/distribution/policies.json` or `Contents/Resources/mozilla.cfg` is wiped on every upgrade. The weekly launchd agent at Sunday 03:00 runs the upgrade and then reapplies the in-repo policies back into the bundle. Without that agent, every cask upgrade silently un-hardens the browser.

### Why the RSS tripwire

Goal: **close the window between "advisory published" and "cask rebuilt".** Mozilla publishes Firefox / Thunderbird security advisories on their own schedule; the LibreWolf cask typically lags by a few days. Waiting for the Sunday auto-upgrade means running a version with a known public vulnerability for up to a week. A daily poll of Mozilla's advisory RSS feed posts a macOS notification on new GUIDs so the user can manually `brew upgrade --cask librewolf` as soon as a build is available.

### Fingerprinting posture

Decision applied 2026-05-01: per-eTLD+1 randomisation engine on, RFP off, on every named profile. The per-profile split is in *what state survives* (clean wipes on shutdown, daily persists), not in the fingerprinting engine.

| Profile | RFP | FPP | Letterboxing |
|---------|-----|-----|--------------|
| `daily` | off (explicit) | on | off |
| `clean` | off (explicit) | on | off |
| Tor Browser | — | — | — (untouched; uses Tor Project's calibration) |

**Conservative starting set:** `privacy.fingerprintingProtection = true` + `.pbmode = true`, with `privacy.resistFingerprinting = false` and `.letterboxing = false` pinned explicitly. **No `granularOverrides` preloaded** — LibreWolf ships a curated default override list from Mozilla's remote-settings collection; entries are added only when a specific site breaks.

**FPP target override applied 2026-05-02 (audit-driven):** `privacy.fingerprintingProtection.overrides = "+AllTargets,-JSDateTimeUTC"`. The 2026-05-01 fingerprint audit found JS Date / Intl reporting `Atlantic/Reykjavik` (GMT+0) while the network IP identifies as Tokyo — a cross-layer contradiction that adds correlation signal without paying anonymity benefit on a logged-in profile. The `+AllTargets` anchor keeps every other Mozilla-curated FPP target at default-on; `-JSDateTimeUTC` peels off only the timezone target.

**WebRTC posture, same audit:** `media.peerconnection.enabled = false` on every named profile. The prior posture (peerconnection on with ICE-layer scrubbing) closed the local-IP leak but still exposed public IPv4 / IPv6 through srflx candidates — confirmed in CreepJS and BrowserLeaks. User does not use voice/video calls in LibreWolf; turning the API off entirely is the right posture. **Brave is the documented call-path fallback** if a future need surfaces.

### Privacy Stack Viewer

`librewolf-extensions/privacy-stack-viewer/` — a custom MV3 WebExtension that surfaces the active tab's privacy stack as a toolbar popup. Phase 1 (2026-05-04) shipped the UI and all data sources except DNS forwarder attribution; phase 2 (2026-05-07) added the dnstap pipeline that supplies it.

<div class="diagram-section">
  <a href="/artifacts/custom-librewolf/popup-hero.png" class="lightbox">
    <img src="/artifacts/custom-librewolf/popup-hero.png" alt="Privacy Stack Viewer popup — TAB / DNS / SEARCH / PRIVACY STACK sections with forwarder attribution row" loading="lazy" />
  </a>
</div>

**Four popup sections:**

- **TAB** — hostname, IP, TLS version + cipher, ECH state (green = accepted, yellow = extension-present / success-false), cert issuer, HSTS. TLS rows are suppressed for `about:` / `chrome:` / `extension:` / `file:` / `resource:` pages and for the SearXNG loopback host.
- **DNS** — resolver (`127.0.0.1:5335` Unbound) and the upstream DoT forwarders baked from `dns/unbound.conf`. Phase 2 fills in a per-query attribution row: which forwarder resolved this tab's hostname (`via Quad9`, `via Mullvad`, …), or a typed failure reason (`helper_missing` / `collector_unavailable` / `no_evidence` / `ambiguous`) with reason-aware help text.
- **SEARCH** — only renders when the active tab is on `127.0.0.1:8888`. Fetches `/stats` and `/config` from SearXNG and renders the top 8 engines by recent query count with error-rate / cooldown toning; all field accesses wrapped in fallbacks for schema drift tolerance.
- **PRIVACY STACK** — cross-origin sub-request count and up to 3 most-frequent third-party hostnames; static labels for FPP / ETP / WebRTC reflecting project config (deliberately not a runtime `about:config` read — that API surface does not exist for WebExtensions).

**Privacy contract:** hostnames only in third-party rows (full URLs would expose visited paths); no persistence, no telemetry, no disk I/O; zero outbound except two loopback SearXNG endpoints. Documented in `librewolf-extensions/privacy-stack-viewer/PRIVACY.md`.

**Phase 2 plumbing (per-query forwarder attribution):**

```
Unbound (dnstap socket) ──► privacy_stack_dns_observer.collector
                              (10-min / 4096-event ring buffer)
                                       │
                                       ▼
                                 query.sock  (Unix)
                                       │
                                       ▼
                            native_host stdio bridge
                                       │
                                       ▼
                              LibreWolf extension
                              (lookup_forwarder IPC)
```

Stock Homebrew Unbound ships without `dnstap` support, so a repo-managed formula (`dns/homebrew/unbound.rb`) builds Unbound with `--enable-dnstap --with-protobuf-c`. The collector runs as a root-owned `LaunchDaemon` that creates the observer socket *before* Unbound restarts (Unbound attempts to connect exactly once at startup and silently skips dnstap if the socket isn't there). No network listeners, no disk logging of DNS events.

### SearXNG engine policy

**Disabled (never enable these):** Google, Bing, Yandex — **including every category variant** (`google_images`, `google_news`, `google_videos`, `google_scholar`, `google_play_apps`, `google_play_movies`, `bing_images`, `bing_news`, `bing_videos`, `yandex_images`, `yandex_music`). Disabling only the general-category entry leaves images / news / videos / scholar firing — observed 2026-05-02 before the fan-out lockdown.

**Primary general-search lanes — curl_cffi sidecars:** DDG, Brave, Mojeek, Karmasearch. Each is a SearXNG `engine_type = "offline"` module that imports `search_curl.engines.<name>` directly and bypasses SearXNG's httpx outgoing client. `curl_cffi` performs a Chrome-shaped TLS handshake (`impersonate=chrome120`) that survives the WAF cascades that broke the previous httpx-based posture.

**Recovery:** if a sidecar is challenged (90 s in-process cooldown on a challenge body or `429 Suspended`), the unblock path is to open the engine in LibreWolf and clear the IP-rep flag manually. ### Update cadence

| Agent | Schedule | What it does |
|---|---|---|
| `com.user.librewolf-update` | Sunday 03:00 weekly | `brew upgrade --cask librewolf`, then reapplies `librewolf/policies.json` (and `mozilla.cfg` + `autoconfig.js` if present) from the repo into the app bundle |
| `com.user.moz-advisory` | Daily 09:00 | Polls Mozilla Security Advisories RSS as a tripwire; posts a macOS notification when a new advisory appears so the user can upgrade early |
| `com.user.librewolf-customizations` | At login | Re-runs `install-profile-files.sh` as a self-heal (re-points symlinks if anything has gone stale after a worktree deletion) |
| `com.user.dnsmasq-logrotate` | Daily | Rotates `~/Library/Logs/dnsmasq/queries.log`, keeps 14 dated archives |
| `com.user.privacy-stack-dns-observer` | At boot | Root-owned LaunchDaemon — starts the dnstap collector, chowns the query socket to the invoking user |

`RunAtLoad=false` on the update and advisory agents — they run only at their scheduled time, not on login. The reapply agent uses `sudo cp` to write into the app bundle; a NOPASSWD sudoers rule scoped to the exact `cp` paths is required for unattended runs.

Daily runs Sidebery for vertical tabs (native tab bar hidden via `librewolf/userChrome.css`), Multi-Account Containers + Container Tabs Shortcuts for per-identity isolation, uBlock Origin with redirect resources, Skip Redirect, and the Privacy Stack Viewer. Location Guard NG and Privacy Badger were evaluated and **deliberately not installed** — uBO already handles trackers; `geo.enabled = false` is pinned, so there's nothing for a geolocation spoofer to spoof.

Two AppleScript launcher bundles (`LibreWolf-Daily.app`, `LibreWolf-Clean.app`) live in `/Applications/Browsers/` and go in the Dock. Both pass `--no-remote -P <name>` — without `--no-remote`, the second launcher attaches to the first profile's running process instead of opening its own. The plain `LibreWolf.app` does **not** belong in the Dock.

### Philosophy

This is not a fork, a distribution, or a brand. It's a deliberately small repo that turns *somebody else's hardened browser* into *the one this specific machine runs*, against this specific threat model, with every decision recorded against the failure mode it avoids. The DNS stack, the SearXNG instance, and the WebExtension exist because the browser alone cannot enforce its posture from inside its own process — the network, the resolver, and the search lane are part of the same surface, and any link in that chain that points off-machine becomes the weak link.

**The browser is the artifact. The chain is the system.**
